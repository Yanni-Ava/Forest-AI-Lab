# 9月后续执行周计划

负责人：王思丹  
适用阶段：AI Alpha V0.5 推进阶段

## 总目标

9 月后续工作的重点是把当前 Alpha V0.4 从“流程验证”推进到“真实数据驱动的可展示模型”。核心不是继续堆实验次数，而是让真实图片、人工标注、模型训练、Web 展示和阶段汇报形成闭环。

## 第 1 周：真实数据接收与筛选

时间建议：9.3—9.8

### 负责人任务

1. 向数据模块同学发送数据要求。
2. 接收第一批校园/森林图片。
3. 检查图片是否符合训练要求。
4. 删除或暂缓不合格图片。
5. 使用 `prepare_campus_image_batch.py` 批量整理合格图片。
6. 补全数据来源清单。
7. 使用 `validate_campus_data_intake.py` 完成数据接收检查。

### 验收产物

- `AI/datasets/campus_forest_v05/metadata_template.csv`
- `AI/datasets/campus_forest_v05/sources.md`
- 第一批图片质量筛选记录
- 数据接收检查报告

### 达标标准

- 至少接收 50 张图片。
- 至少 35 张图片可进入训练集候选。
- 每张图片来源清楚。
- test 集图片单独保留，不参与训练调参。

## 第 2 周：LabelMe 人工标注

时间建议：9.9—9.15

### 负责人任务

1. 按 `docs/9月人工标注规范.md` 统一标注口径。
2. 使用 LabelMe 标注树木/植被 polygon。
3. 抽查 train/val/test 三类标注质量。
4. 将 LabelMe 标注导回 YOLO segmentation 格式。
5. 运行数据集检查。

### 验收产物

- LabelMe JSON 标注文件
- YOLO labels
- 数据集检查结果
- 修标前后对比图

### 达标标准

- 所有训练图片均有对应标注。
- 标注不大面积覆盖天空、水面、道路、建筑。
- 数据集检查无 errors。

## 第 3 周：Alpha V0.5 模型训练与对比

时间建议：9.16—9.22

### 负责人任务

1. 使用 `campus_forest_v05` 训练 Alpha V0.5。
2. 保存训练参数、指标、结果图。
3. 与 Bootstrap、V0.4 进行对比。
4. 判断是否替换 Demo 主模型。
5. 更新模型选择记录。

### 验收产物

- Alpha V0.5 训练目录
- 实验记录文档
- 模型对比表
- 测试集预测图
- 更新后的 Demo 模型选择记录

### 达标标准

- test 集有可解释结果。
- 默认阈值下结果图不能明显乱检。
- 指标或展示效果至少一项明显优于当前 Demo 主模型。

## 第 4 周：Web 展示与阶段汇报

时间建议：9.23—9.30

### 负责人任务

1. 若 V0.5 稳定，则接入 Web/API Demo。
2. 若 V0.5 不稳定，则保留现有 Demo 主模型，并把 V0.5 作为实验记录。
3. 整理阶段汇报材料。
4. 更新 GitHub。
5. 准备论文和软著材料目录。

### 验收产物

- 可运行 Web Demo
- 阶段汇报文档
- GitHub 提交记录
- 论文实验材料
- 软著功能模块说明

### 达标标准

- Demo 可现场运行。
- 文档能解释每个模型版本为什么保留或不替换。
- GitHub 文件结构清楚。
- 后续论文/软著材料可继续沿用。

## 风险控制

| 风险 | 处理方式 |
| --- | --- |
| 数据同学交图慢 | 先用已有公开图继续补流程，但不宣称正式模型 |
| 图片来源不清楚 | 不进入论文实验，只作为内部测试 |
| 标注质量不稳定 | 先抽查总览图，再导回训练 |
| V0.5 指标不理想 | 不替换 Demo 主模型，保留为实验记录 |
| Web 展示出错 | 保留 API 文档和图片检测作为备用演示 |

## 当前优先级

1. 催真实图片和来源清单。
2. 做 LabelMe 标注。
3. 训练 V0.5。
4. 再决定是否替换 Demo 主模型。
